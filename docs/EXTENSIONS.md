4. **Findings log:** Record any issues found and fixed in the git commit message for the step.

## CodeRabbit

**What it is:** An AI-powered code-review tool that analyses diffs for security issues, race conditions, error handling gaps, type safety violations, and style problems.

**Discovery result:** `NOT AVAILABLE` — no CLI binary (`where.exe coderabbit` returned nothing); not in marketplace or skills.

**Fallback = Manual CodeRabbit Routine:**

At every Step Close, perform this review pass manually before committing:

1. Run `git diff --staged` (or `git diff HEAD`) to see the full diff.
2. For each changed file, check:
   - **Security:** No secret in code, no unsanitised user input reaching Mongo queries, no missing `requirePermission` on a new route.
   - **Race conditions:** Any shared mutable state accessed outside a transaction?
   - **Error handling:** Every `async` function has a `try/catch` or is inside the Express error middleware chain; every rejected promise is surfaced.
   - **Type safety:** No `any` without a `// eslint-disable` comment explaining why; no unchecked casts.
   - **Append-only rule:** No `.updateOne`/`.deleteOne` on `audit_logs`, `execution_ledger`, or `shipment_events`.
3. Fix every actionable finding.
4. In the `git commit` message, add a `Review:` trailer listing findings that were intentionally ignored and the reason (e.g., `Review: ignored ESLint max-len on the generated Zod schema — generated code`).
